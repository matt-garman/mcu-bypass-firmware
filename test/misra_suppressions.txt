# cppcheck suppressions shared by the project's five MISRA-C:2012 analysis lanes
# (Classic/shared, AVR-XT, PIC10F322, PIC10F320, PIC12F675). All five consume at
# least one entry. PIC10F322 and PIC12F675 need no MISRA-rule deviation, but each
# has one file-scoped misra-config analyzer accommodation; see
# MISRA_COMPLIANCE.md, "Suppression review".

# This file holds DOCUMENTED, PROJECT-SPECIFIC finding suppressions. D-1 records
# actual MISRA deviations; D-2/D-3 are advisory analyzer artifacts for
# declarations used elsewhere in the project; D-4 contains analyzer
# accommodations, including one diagnostic that is not a MISRA rule. Every entry
# maps to a classified D-n record in MISRA_COMPLIANCE.md with its rationale. An
# entry without a matching record is a compliance defect.

# Scope: suppressions are PER FILE (errorId:filename), not project-wide. A new
# instance of one of these rules in a NEW file therefore still surfaces and
# fails its MISRA lane. Another finding with the same ID in an already-listed
# file is covered, so suppression changes also require an unsuppressed review.

# cppcheck 2.13.0 itself sets --error-exitcode only for findings located in the
# FILE PASSED ON THE COMMAND LINE. Every gating recipe therefore forces a
# machine-readable diagnostic template and passes captured output through
# test/misra_output_gate.py. The parser normalizes relative and absolute paths
# and independently fails every unwaived finding in authored src/*.c or src/*.h.
# A committed fake-cppcheck probe emits a zero-exit Required-rule finding in an
# authored header and proves that only the exact rule:file entry restores clean.

# Out of scope (handled on cppcheck command lines in the Makefile, not here):
# findings located in adopted avr-libc/avr-gcc, ATtiny DFP, XC8/PIC DFP, and
# C-library headers.

# (cppcheck parses a line that is exactly "#" as a malformed suppression, so
# blank separator lines below are left empty rather than commented.)

# --- D-2: cross-translation-unit shared pin macros (Rule 2.5) ----------------
# The per-MCU pin maps are project-wide sources of truth. Modular shells consume
# each active map, while individual driver TUs use variant-specific subsets;
# cppcheck's TU-local and cross-configuration processing can report declarations
# used elsewhere, including directives from inactive maps. `bypass_config.h` has
# the same split: the shared core and four modular shells consume both
# thresholds, while mute/relay driver assertions consume RELEASE_THRESH but not
# PRESSED_THRESH. See D-2.
misra-c2012-2.5:src/bypass_pins_avr_classic.h
misra-c2012-2.5:src/bypass_pins_pic10f322.h
misra-c2012-2.5:src/bypass_config.h
# The AVR-XT (ATtiny202) pin map is the third per-MCU map and behaves exactly
# like the two above: bypass_output_common.h selects a map with #if/#elif, so
# the unselected AVR-XT map is recorded in cppcheck's cross-config directive
# list and its macros read "unused" in the classic and PIC runs. Same D-2
# cross-config artifact.
misra-c2012-2.5:src/bypass_pins_avr_xt.h
# The PIC12F675 map is the fourth, and behaves identically -- the classic lane
# reports three of its macros unused per checked translation unit. Recorded for
# the same reason and with the same standing as the three above.
misra-c2012-2.5:src/bypass_pins_pic12f675.h
# bypass_output_common.h is the header that SELECTS one of those four maps, and
# it now also carries WDT_PET_TO_PET_MAX_MS() -- the watchdog pet-to-pet budget
# whose per-target terms the maps supply. All three output-driver TUs expand it;
# the four modular shells include the header for its map selection and do not,
# so the shell runs report it unused. Same cross-TU artifact as the maps it
# selects, recorded under D-2 with them.
misra-c2012-2.5:src/bypass_output_common.h

# --- D-3: shared algorithm-type header (Rules 2.3, 2.4) ----------------------
# bypass_types.h is the single source of truth for the debounce/bypass algorithm
# types. bypass_hw_iface.h now includes it for effect_state_t (the argument to
# hw_is_sanity_check_failed), so every output-driver TU transitively sees
# pin_state_t and debounce_context_t as well -- types used only by the core
# (bypass_pure.c) and the per-MCU shells, never by an output driver. cppcheck
# analyzes each TU alone and reports the unreferenced type (2.3) and its tag
# (2.4) as unused. Not dead code: each is used by some TU. See MISRA_COMPLIANCE.md D-3.
misra-c2012-2.3:src/bypass_types.h
misra-c2012-2.4:src/bypass_types.h

# --- D-4: PIC device-SFR symbol resolution (misra-config) --------------------
# NOT a MISRA rule deviation. `misra-config` is cppcheck's own diagnostic for
# "the addon could not resolve this symbol". PIC10F322 and PIC12F675 report this
# for volatile SFR bitfield reads in their tick polls; their former broad command-
# line suppression is now one exact source file each, so an occurrence in any
# header or other source reaches the output gate.
misra-config:src/bypass_mcu_pic10f322.c
misra-config:src/bypass_mcu_pic12f675.c
# PIC10F320 reports the same diagnostic for `PIR1bits`/`TMR2IF` in its 1 ms tick
# wait. On this file the addon loses the device symbol table, bisected to its
# heavy in-function `static_assert` use. Scoped to this file deliberately. All
# other finding IDs remain visible; Rule 14.4 injection confirms an unrelated
# MISRA finding still fails. See MISRA_COMPLIANCE.md D-4.
misra-config:src/bypass_mcu_pic10f320.c
# Same root cause, rule side: TICK_PERIOD_MS and WDT_MIN_PERIOD_MS are consumed
# ONLY inside static_assert() expressions, which the addon cannot see for this
# file, so it reports them as unused macros. They are demonstrably used -- the
# asserts they feed enforce the complete blocking + ISR-duty + tick + loop-work
# wall-clock budget below the worst-case WDT period at compile time. Waived
# explicitly rather than left to pass silently. See MISRA_COMPLIANCE.md D-4.
misra-c2012-2.5:src/bypass_mcu_pic10f320.c

# --- D-5: avr-libc ATOMIC_BLOCK vendor macro (Rules 12.3, 14.2; unreadVariable) ---
# The F2 context-SEU feature (BYPASS_CTX_CHECK, docs/context_seu_detection.md)
# needs main()'s snapshot-through-publish transaction to be atomic w.r.t. the
# timer ISR, so the two AVR ISR shells use avr-libc's
# ATOMIC_BLOCK(ATOMIC_RESTORESTATE) from
# <util/atomic.h> -- the recommended idiom for interrupt-atomic access. It expands
# to a run-once for-loop whose init clause uses the comma operator (12.3) and a
# __cleanup__-attributed SREG-save local, so the addon reports a non-well-formed
# for loop (14.2) and cppcheck's native --enable=style reports the vendor-internal
# save local as unread (the __cleanup__ read is invisible to it). Same class as
# D-1: a deviation forced by an adopted avr-libc macro, not authored logic. The
# PIC shells are single-owner polled loops and use no such macro. Only the MISRA
# lane consumes this file; the parallel non-MISRA cppcheck lane waives the same
# unreadVariable via an inline --suppress on its command line (CPPCHECK_FLAGS /
# XT_CPPCHECK_FLAGS). See MISRA_COMPLIANCE.md D-5.
misra-c2012-12.3:src/bypass_mcu_avr_classic.c
misra-c2012-12.3:src/bypass_mcu_avr_xt.c
misra-c2012-14.2:src/bypass_mcu_avr_classic.c
misra-c2012-14.2:src/bypass_mcu_avr_xt.c
unreadVariable:src/bypass_mcu_avr_classic.c
