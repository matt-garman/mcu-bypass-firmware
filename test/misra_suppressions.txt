# cppcheck suppressions shared by the project's five MISRA-C:2012 analysis lanes
# (Classic/shared, AVR-XT, PIC10F322, PIC10F320, PIC12F675). Three of them
# currently consume an entry: the PIC10F322 and PIC12F675 shells analyze clean
# against an EMPTY version of this file -- see MISRA_COMPLIANCE.md, "Suppression
# review".

# This file holds DOCUMENTED, PROJECT-SPECIFIC finding suppressions. D-1 records
# actual MISRA deviations; D-2/D-3 are advisory analyzer artifacts for
# declarations used elsewhere in the project; D-4 contains analyzer
# accommodations, including one diagnostic that is not a MISRA rule. Every entry
# maps to a classified D-n record in MISRA_COMPLIANCE.md with its rationale. An
# entry without a matching record is a compliance defect.

# Scope: suppressions are PER FILE (errorId:filename), not project-wide. A new
# instance of one of these rules in a NEW file therefore still surfaces and
# fails its MISRA lane. Another finding with the same ID in an already-listed
# file is covered, so suppression changes also require an unsuppressed review.

# ...with ONE measured caveat, which is why the entries below are described as
# policy scope rather than as the gate. With cppcheck 2.13.0, --error-exitcode
# is set only by findings located in the FILE PASSED ON THE COMMAND LINE.
# Findings located in an included HEADER are printed but do not fail the lane,
# so the header entries below (the pin maps, bypass_config.h, bypass_types.h)
# suppress output rather than a failure today. Measured both ways: dropping
# misra-c2012-11.4:src/bypass_mcu_avr_classic.c (a .c entry) fails
# `make analyze-misra` with 30 findings, while dropping
# misra-c2012-2.3:src/bypass_types.h or misra-c2012-2.5:src/bypass_pins_avr_xt.h
# (header entries) leaves it green. They are kept, and a new map is added
# alongside them, so the policy stays complete if a later cppcheck starts
# gating header findings. See TODO.md T25-misra-header-gate.

# Out of scope (handled on cppcheck command lines in the Makefile, not here):
# findings located in adopted avr-libc/avr-gcc, ATtiny DFP, XC8/PIC DFP, and
# C-library headers.

# (cppcheck parses a line that is exactly "#" as a malformed suppression, so
# blank separator lines below are left empty rather than commented.)

# --- D-2: cross-translation-unit shared pin macros (Rule 2.5) ----------------
# The per-MCU pin maps are project-wide sources of truth. Modular shells consume
# each active map, while individual driver TUs use variant-specific subsets;
# cppcheck's TU-local and cross-configuration processing can report declarations
# used elsewhere, including directives from inactive maps. `bypass_config.h` has
# the same split: the shared core and three modular shells consume both
# thresholds, while mute/relay driver assertions consume RELEASE_THRESH but not
# PRESSED_THRESH. See D-2.
misra-c2012-2.5:src/bypass_pins_avr_classic.h
misra-c2012-2.5:src/bypass_pins_pic10f322.h
misra-c2012-2.5:src/bypass_config.h
# The AVR-XT (ATtiny202) pin map is the third per-MCU map and behaves exactly
# like the two above: bypass_output_common.h selects a map with #if/#elif, so
# the unselected AVR-XT map is recorded in cppcheck's cross-config directive
# list and its macros read "unused" in the classic and PIC runs. Same D-2
# cross-config artifact.
misra-c2012-2.5:src/bypass_pins_avr_xt.h
# The PIC12F675 map is the fourth, and behaves identically -- the classic lane

# --- D-3: shared algorithm-type header (Rules 2.3, 2.4) ----------------------
# bypass_types.h is the single source of truth for the debounce/bypass algorithm
# types. bypass_hw_iface.h now includes it for effect_state_t (the argument to
# hw_is_sanity_check_failed), so every output-driver TU transitively sees
# pin_state_t and debounce_context_t as well -- types used only by the core
# (bypass_pure.c) and the per-MCU shells, never by an output driver. cppcheck
# analyzes each TU alone and reports the unreferenced type (2.3) and its tag
# (2.4) as unused. Not dead code: each is used by some TU. See MISRA_COMPLIANCE.md D-3.
misra-c2012-2.3:src/bypass_types.h
misra-c2012-2.4:src/bypass_types.h

# --- D-4: PIC10F320 device-SFR symbol resolution (misra-config) --------------
# NOT a MISRA rule deviation. `misra-config` is cppcheck's own diagnostic for
# "the addon could not resolve this symbol" -- here `PIR1bits`/`TMR2IF` in the
# 1 ms tick wait. The declaration is present and correct: the analogous
# statement against the sibling PIC10F322 header from the same DFP
# pack analyzes clean. The addon loses the device symbol table on this file,
# bisected to its heavy in-function `static_assert` use.
# Scoped to this file deliberately. All other finding IDs remain visible, but
# this entry covers every `misra-config` diagnostic attributed to the file;
# Rule 14.4 injection was used to confirm an unrelated MISRA finding still fails.
# See MISRA_COMPLIANCE.md D-4.
misra-config:src/bypass_mcu_pic10f320.c
# Same root cause, rule side: TICK_PERIOD_MS and WDT_MIN_PERIOD_MS are consumed
# ONLY inside static_assert() expressions, which the addon cannot see for this
# file, so it reports them as unused macros. They are demonstrably used -- the
# asserts they feed are what enforce "1 ms tick + blocking pulse < worst-case
# WDT period" at compile time. Waived explicitly rather than left to pass
# silently. See MISRA_COMPLIANCE.md D-4.
misra-c2012-2.5:src/bypass_mcu_pic10f320.c
