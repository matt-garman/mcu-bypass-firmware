# Every published file a release does not sign for itself.
#
# A release ships SHA256SUMS over its images and programming helpers, so those
# stay verifiable from the release directory alone. Nothing covered the rest --
# the evidence logs, QUALIFICATION, MANIFEST.md, README.md, and SHA256SUMS.asc
# itself. Those files are the qualification record; they are not reproducible
# from source, and once published they are the only account of what was run.
# This is their record.
#
# Together with each release's own SHA256SUMS this partitions every published
# file exactly once. test_published_release_immutability.py enforces the
# partition, so a file added to a published release is covered by one list or
# the other, never by neither.
#
# It is an ordinary sha256sum check file, deliberately: from the repository
# root,
#
#     sha256sum -c test/published_release_digests.txt
#
# reproduces the central claim with coreutils and no Python at all.
#
# release/README.md is not here. It is current documentation -- the trust model
# and the standing safety warning -- and it is meant to change.
#
# CHANGING A LINE HERE REWRITES HISTORY. A published release is what its
# recipients already hold; a digest edited until the run goes green retires
# that account silently. Amendments to a published release are possible and
# have happened once (the v0.9.0-v0.9.2 TMUX errata), but they are a deliberate
# act recorded in the gate beside the reason, not a number replaced here.
#
# A new release appends a block after SHA256SUMS.asc is created, verifies the
# complete register, and commits that append with release/vX.Y.Z/. Generate it
# with:
#
#     ./test/test_published_release_immutability.py --print-record vX.Y.Z >> test/published_release_digests.txt
#     ./test/test_published_release_immutability.py
